# 城市公共交通刷卡数据客流分析

4 人小组 Hadoop 课程实战项目：对公交刷卡记录做离线分析，算出 12 个客流指标。每人负责 3 个、各自提交到本仓库，最后由组长汇总成一张结果表和一个展示页面。

## 技术栈（全组统一，不要各装各的）

| 项目 | 就定这个 |
|---|---|
| 存数据 | Hadoop 3.4.1 自带的 HDFS |
| 算指标 | Hive 3.1.3，12 个指标全部写 SQL |
| 运行环境 | JDK 8，全组连组长那一套，不在自己电脑另装 |
| 交作业 | Git + GitHub，本仓库 |
| 组长才要管的 | Shell 脚本做汇总、一个 HTML 页面做展示 |
| 一律不装 | Java MapReduce、Spark、Flink、Kafka、Docker、Maven |

版本由组长定一次，全组照抄；实验室给了别的版本就全组一起换，谁都不许自己装、自己升级。

## 分工（详见 docs/分工方案.md）

| 谁 | 做哪 3 个 | 说人话就是 |
|---|---|---|
| 组长 | 01 日均刷卡量、02 高峰小时系数、08 早晚高峰客流比 | 一天多少人、几点最挤、早上人多还是晚上人多 |
| 组员 1 | 03 各线路日均客流、04 各站点日均客流、07 客流空间集中度 | 哪条线、哪个站人最多 |
| 组员 2 | 05 工作日/周末客流比、06 节假日客流变化率、09 月度客流趋势斜率 | 平时和假期差多少、客流有没有逐月变多 |
| 组员 3 | 10 站点进出比、11 工作日客流稳定性、12 累计计数异常率 | 站点是住人的还是上班的、客流稳不稳、数据有没有错 |

## 12 个指标

| 编号 | 指标 | 公式 | 负责人 |
|---|---|---|---|
| 01 | 日均刷卡量 | 总进出站客流 / 统计天数 | 组长 |
| 02 | 高峰小时系数 | 高峰小时客流 / 全日客流 | 组长 |
| 03 | 各线路日均客流 | 按 LINENAME 聚合日客流 / 统计天数 | 组员 1 |
| 04 | 各站点日均客流 | 按站点聚合日客流 / 统计天数 | 组员 1 |
| 05 | 工作日/周末客流比 | 工作日日均客流 / 周末日均客流 | 组员 2 |
| 06 | 节假日客流变化率 | (节假日日均 - 非节假日日均) / 非节假日日均 | 组员 2 |
| 07 | 客流空间集中度 | Top10 站点客流 / 总客流 | 组员 1 |
| 08 | 早晚高峰客流比 | 早高峰客流 / 晚高峰客流 | 组长 |
| 09 | 月度客流趋势斜率 | 月日均客流对月份序号的回归斜率 | 组员 2 |
| 10 | 站点进出比 | SUM(出站客流) / SUM(进站客流) | 组员 3 |
| 11 | 工作日客流稳定性 | STD(工作日日客流) / MEAN(工作日日客流) | 组员 3 |
| 12 | 累计计数异常率 | (差分负值数 + 重复记录数) / 总差分记录数 | 组员 3 |

## 统一口径（算之前对一遍，改动须全组同意）

1. 客流 = 1 条刷卡记录算 1 人次，进站出站都算，不按卡号去重；统计天数 = 有刷卡记录的不同日期数。
2. 时间：日期取刷卡时间前 10 位（2026-04-01），小时取第 12-13 位。指标 02 的「高峰小时」= 当天按小时数客流后最大的那个小时；指标 08 固定早 7:00-9:00（7、8 点）/ 晚 17:00-19:00（17、18 点）。
3. 日期标签一律查 data/dim_date.csv（含调休）：工作日 = is_workday=1；周末 = is_weekend=1 且 is_holiday=0；「非节假日」= is_holiday=0 的所有日子。不能用星期一到星期五硬判断。
4. 站点 / 线路按名字整体聚合，同名合并、不拆单线；Top10 按站点客流量从大到小取前 10。
5. 指标 09 用最小二乘斜率（x = 月份序号 1、2、3…，y = 月日均客流）；指标 12 按卡号+时间排好序，相邻两条累计计数相减，差值 <0 或 =0 算异常，分母为总差分条数。
6. 所有数值保留 4 位小数；结果文件 UTF-8 CSV，列固定 `metric_id,metric_name,dim_key,value,unit`。

## 目录

```
city-bus-flow-analysis/
├── README.md
├── docs/           分工方案
├── data/           组长放刷卡数据和日历表，其他人只读
├── setup/          组长放建表脚本
├── sql/            每人放自己的 .sql 文件
├── scripts/        组长放汇总脚本
├── output/         每人放自己的 3 个结果 CSV
└── dashboard/      展示页面
```

## 每人交什么

- 1 个 `.sql` 文件（3 条 SQL，每条上面写一句中文说明这题在算什么）
- 3 个结果 CSV（`output/metric_XX.csv`，格式见口径第 6 条）
- 只改自己目录下的文件，不要动别人的

## 怎么跑

1. 组长：把数据和日历表放进 HDFS，执行 `setup/` 里的建表脚本（一次即可）。
2. 每人：`beeline -u jdbc:hive2://<主机>:10000/transit -f sql/member-自己字母.sql`
3. 组长：`bash scripts/run_all.sh` 生成 `result.csv`，打开 `dashboard/` 查看 12 个指标。
